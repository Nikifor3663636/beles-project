# Beles: сайт и админка на одном хостинге

Сайт: `/`. Админка: `/admin`. Обращения: `/api/feedback`.
Это самостоятельный Node.js-проект. Framer, его подписка, редактор и CMS для работы не нужны. Текущий Framer-проект не изменён.

Актуальные операции, PostgreSQL, S3/VPS, роли и восстановление: [OPERATIONS_TZ_RU.md](OPERATIONS_TZ_RU.md). Проверки и ограничения: [ACCEPTANCE_TZ_RU.md](ACCEPTANCE_TZ_RU.md).

## Что перенесено

Дизайн, мобильная версия, переключение UA/EN, каталог, карточки и модальные окна, PDF-презентации, партнёры, панель доступности и TikTok из предоставленного TSX. Данные из `Catalog (1).csv`: 34 бренда, 386 товаров, 20 презентаций, 9 партнёров и 24 записи текстов/контактов. Самокат MAXPLAY HT-38-2 добавлен/обновлён с предварительными характеристиками сезона 2027.

Админка: вход с паролем, создание и редактирование записей, поиск и фильтр бренда, сортировка, публикация/скрытие, удаление с подтверждением, загрузка PNG/JPG/WebP/GIF/AVIF/PDF до 20 МБ для изображений и 60 МБ для PDF, просмотр обращений и отметка «Опрацьовано», смена пароля, экспорт резервной копии JSON. Переименование бренда обновляет поле Brand у связанных товаров и презентаций. Нельзя удалить бренд с привязанными записями.

## Быстрый запуск на компьютере

1. Установите Node.js 22 или новее.
2. Распакуйте архив. Откройте терминал в папке `beles-project`.
3. Выполните `npm ci`, затем `npm start`.
4. Откройте `http://localhost:3000/admin`.
5. Скопируйте одноразовый setup-код из терминала, задайте логин и пароль длиной от 12 символов. После создания администратора войдите с этими данными.
6. Сайт доступен на `http://localhost:3000`.

Готового общего пароля в архиве нет. Setup-код меняется при перезапуске до создания первого администратора. После первой настройки создаются `data/admin.json` и постоянная отметка `data/admin.initialized`. Повторная регистрация закрыта на сервере, в том числе после перезапуска и при случайном удалении admin.json. Главный администратор может добавить одного второго пользователя в «Мій акаунт». Максимум — два администратора. Публичная регистрация закрыта. Менять пароль можно в «Мій акаунт». Если пароль утрачен, владелец хостинга должен восстановить файлы учётной записи из своей резервной копии; обычный посетитель не может создать нового администратора.

## Что редактировать

В админке выберите нужный раздел. У изображения/PDF можно вставить HTTPS-ссылку или загрузить файл. После загрузки обязательно нажмите «Зберегти зміни». Названия брендов у товаров выбираются из списка. Item Key должен быть уникален в пределах типа записи; для существующих записей лучше сохранять его.

Для брендов категории используют существующие ключи, например `large;vehicles;outdoors`. Сохраните принятые в исходном каталоге ключи, чтобы работали фильтры. Характеристики заполняются в Features UA/EN: одна строка `Назва: значення`. Текстовые записи используют существующие имена (`hero_desc`, `about_text`, `phone`, `email` и т. д.). Их имена не меняйте — меняйте значения UA/EN и ссылку. Служебный `feedback_endpoint` сервер направляет на собственный API автоматически.

Изменения сохраняются на сервере сразу. Чтобы увидеть их на уже открытом сайте, обновите страницу. Это не совместный редактор в реальном времени: при одновременном сохранении старой версии админка попросит обновить данные вместо перезаписи чужих изменений.

## Размещение на одном хостинге

Нужен тариф с постоянно работающим Node.js-приложением и записываемым диском. Покупка одного домена и SSL сама по себе не предоставляет такой хостинг. Обычный тариф только с PHP без поддержки Node.js для этого архива не подходит.

### HOSTiQ / панель запуска Node.js

Сначала уточните у поддержки, позволяет ли ваш тариф запускать Node.js HTTP-приложение. Если да:

1. Загрузите содержимое проекта в отдельную папку приложения.
2. В панели создайте Node.js-приложение: корень — папка проекта, startup file — `server.cjs`, Node.js 22+.
3. Укажите URL приложения `https://belesbrands.com.ua`. Используйте порт и интерфейс, которые требует панель: приложение читает `PORT` и `HOST` из окружения. Если требуется доступ извне процесса, задайте `HOST=0.0.0.0`.
4. Добавьте переменные `PUBLIC_URL=https://belesbrands.com.ua` и `COOKIE_SECURE=true`.
5. Дайте процессу права записи в `data/` и `uploads/`. Не размещайте эти папки в чужом общем статическом корне.
6. Настройте DNS домена на адрес этого хостинга по его инструкции. Не используйте IP Framer.
7. Включите HTTPS в панели хостинга. Здесь сертификат обеспечивает ваш хостинг, а не Framer.
8. Запустите приложение. Возьмите setup-код из логов запуска и создайте администратора по `/admin`.

Точные названия пунктов панели зависят от тарифа. Эти действия ещё не выполнены в вашем аккаунте: архив не опубликован, DNS не изменён, хостинг не приобретён.

### VPS / Docker

Есть Dockerfile и compose.yaml. Перед запуском проверьте права владельца каталогов для пользователя контейнера node (UID 1000). Запустите `docker compose up -d --build`, логи: `docker compose logs beles`. Поставьте Nginx/Caddy перед приложением и настройте HTTPS; пример location-блока — `nginx.example.conf`. Не открывайте незащищённую админку через HTTP в интернете. `COOKIE_SECURE=true` требует HTTPS. Для локального HTTP эту переменную не задавайте.

## Файлы и резервные копии

- `data/catalog.json` — текущее содержимое каталога.
- `data/base.html` — исходный дизайн и поведение сайта.
- `render.cjs` — связывает данные с дизайном.
- `data/admin.json` — хеш пароля и соль, создаётся при настройке.
- `data/admin.initialized` — постоянная блокировка повторной регистрации.
- `data/asset-manifest.json` — соответствие исходных ссылок локальным файлам.
- `data/feedback.json` — обращения, создаётся при первом сообщении.
- `uploads/` — новые изображения и PDF.
- `data/catalog.previous.json` — предыдущая версия каталога перед последним изменением.

Кнопка «Резервна копія» выгружает JSON каталога и обращений. Для полного восстановления сохраняйте также всю папку `uploads/` и `data/`; JSON-экспорт не содержит байты загруженных файлов. Для ручного восстановления остановите приложение и замените `data/catalog.json` массивом `rows` из резервного JSON (и `data/feedback.json` массивом `feedback` при необходимости). Восстановите uploads, затем запустите сервер.

Используется атомарная запись JSON, без отдельного сервера базы данных. Запускайте один экземпляр Node.js на постоянном диске. Не используйте кластер, несколько реплик или serverless с временным диском: для такой инфраструктуры нужна замена хранилища на базу данных.

## Все исходные медиа включены

Скачаны файлы по всем 484 найденным ссылкам на изображения и PDF из каталога и дизайна. Все поля Image и PDF File в каталоге ссылаются на локальные файлы в uploads/. Также включены исходное фото самоката, два предоставленных логотипа и пять файлов шрифтов Manrope/Unbounded. PDF-ссылки на отдельные страницы сохранены с указанием страницы, но ведут на локальную копию. Соответствие оригинальных ссылок локальным файлам хранится в data/asset-manifest.json. Внешние ссылки на магазины, соцсети и источники оставлены как ссылки; сайт больше не загружает каталоговые фото и PDF из Framer.

Файлы сохранены в полученном от исходного сервера качестве, без искусственного увеличения разрешения. Папка uploads занимает около 382 МБ плюс шрифты. Не удаляйте файлы по отдельности: они используются записями каталога. PDF поддерживают HTTP Range для частичной загрузки и просмотра больших документов.

Для новых файлов админка принимает изображения и PDF до 150 МБ. Ваш хостинг или обратный прокси может устанавливать меньший предел — увеличьте его при необходимости. В примере Nginx задано client_max_body_size 155m. Фото имеют превью, PDF — кнопку открытия; категории выбираются флажками, технические ключи для новых записей генерируются автоматически. Поиск и фильтры помогают находить записи. При закрытии формы с несохранёнными изменениями появляется предупреждение.

Админка не включает визуальное перетаскивание блоков как во Framer. Она редактирует перечисленные данные; изменение самой верстки делается в `data/base.html`. Новые произвольные поля сами в дизайн не добавляются. Озвучка панели доступности использует возможности исходного сайта и браузера; отдельный платный сервис не подключён. Обращения сохраняются в админке, email/Telegram-уведомления не настроены.

## Проверка

`npm test` запускает изолированный временный сервер и проверяет настройку администратора, авторизацию, создание/удаление товара, конфликт версий, вывод изменений на сайте, отказ загрузки запрещённого типа файла, приём обращения и выход. Тестовые данные не меняют рабочий каталог.

## Дополнительные проверки версии 2

Проверены блокировка публичной повторной регистрации и лимит двух администраторов, включая отсутствие повторной регистрации при утрате файла пароля. Все поля изображений/PDF проверены на локальные пути и существующие файлы. Проверен синтаксис 16 встроенных скриптов сайта. Для админки выполнены DOM-проверки запуска, таблиц, редактора, сохранения, категорий, превью, текстовых подписей и аккаунта; это не заменяет визуальную приёмку в настоящем браузере на вашем хостинге.
