# Структура проекта

Приложение работает на Node.js без сторонних зависимостей во время исполнения. Prettier — только инструмент разработки; он не нужен серверу Railway.

## Сервер

- `server.cjs` — запуск HTTP-сервера, маршруты, сессии и проверка доступа.
- `http-utils.cjs` — JSON-ответы, чтение тела запроса, выдача файлов и HTTP Range.
- `json-store.cjs` — чтение JSON и атомарная замена файла.
- `catalog.cjs` — проверка записи каталога и вычисление ревизии.
- `accounts.cjs` — пароли и ограничение числа администраторов.
- `analytics.cjs` — приём событий, хранение и агрегирование статистики.
- `product-import.cjs` — безопасная загрузка и извлечение данных товара.
- `site-design.cjs` — редактор шаблона, оригиналы, версии и восстановление.
- `design-preview.cjs` — подсветка и выбор блоков внутри изолированного живого предпросмотра.
- `storage.cjs` — расположение постоянных данных и загрузок.
- `render.cjs` — сборка страницы из шаблона и каталога.

## Интерфейс

`data/base.html` содержит исходную страницу, её стили и сценарии. Они остаются вместе, чтобы полный HTML и отдельные блоки были доступны в редакторе сайта. Форматирование раскрывает CSS и JavaScript в читаемые строки, сохраняя значимые пробелы HTML.

`public/admin/` содержит отдельные файлы основного интерфейса, аналитики, интеграций и редактора дизайна. `public/analytics.js` и `public/google-analytics.js` работают на публичной странице. `public/clarity.js` оставлен инертным для старых шаблонов.

Метки `BELES:CATALOG`, `BELES:PRESENTATIONS`, `BELES:CATEGORIES` и `BELES:TRANSLATIONS` в шаблоне — контракт с рендерером. Не удаляйте их при изменении кода. Старые резервные шаблоны без меток поддерживаются отдельно.

## Проверки и стиль

После установки инструментов через `npm ci`:

```sh
npm run format
npm run format:check
npm test
```

Стиль задаётся в `.prettierrc.json` и `.editorconfig`: UTF-8, два пробела, единые кавычки и окончания строк. Служебные данные, загрузки и резервные копии исключены из форматирования. Тесты используют временные каталоги, не меняя рабочий каталог товаров.

## Данные и публикация

На Railway данные находятся в `BELES_STORAGE_DIR`. Опубликованный через админку дизайн имеет приоритет над шаблоном поставки. Если пользовательского дизайна нет, используется актуальный `data/base.html`. `site-original.html` — неизменяемая резервная копия, а не рабочий шаблон; обновление кода не переписывает её.

Перед публикацией выполняйте тесты и проверку форматирования. В Docker копируются серверные модули, `public/`, шаблон и начальный каталог. Не включайте локальные аккаунты, обращения, аналитику и пользовательские версии дизайна в образ.
