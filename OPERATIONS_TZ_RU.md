## Аккаунты

Первый существующий аккаунт получает роль `owner`, сохраняя логин, соль и scrypt-хеш. Второй — `admin`. Сохраняется ранее заказанный предел в два аккаунта. Только владелец создаёт, отключает и удаляет второго администратора, видит его активность, редактирует шаблон, смотрит хранилище и журнал. Удалить/отключить владельца через API нельзя. Обычный администратор работает с каталогом, обращениями и аналитикой, видит только свой профиль и свои сеансы.

В «Мій акаунт» доступны имя, ссылка на аватар, пароль, TOTP и сеансы. Сначала сохраните постоянный `APP_ENCRYPTION_KEY` в менеджере секретов: 32 случайных байта в base64 либо 64 hex-символа. Затем добавьте показанный секрет в TOTP-приложение и подтвердите шестизначным кодом. Восемь резервных кодов показываются один раз, в хранилище остаются только хеши. Каждый код одноразовый; повтор TOTP в том же временном шаге запрещён. При отсутствии серверного ключа настройка честно возвращает ошибку и не включает 2FA.

Смена пароля завершает все сеансы этого аккаунта. Отключение администратора немедленно лишает его доступа. В хранилище записываются хеши токенов сеансов, срок действия и CSRF-токен; браузер получает HttpOnly/SameSite=Strict cookie, на HTTPS — Secure. Шаблон, резервные копии, журнал и файловые операции требуют недавнего подтверждения личности: пять минут после входа/повторной проверки пароля и 2FA. История дизайна хранит десять предыдущих публикаций; исходный HTML хранится отдельно.

## PostgreSQL

Пока `DATABASE_URL` отсутствует, явно используется существующий JSON. Если URL задан, приложение работает только с PostgreSQL. Недоступная БД/отсутствующая схема дают 503 и закрытый setup; пустой каталог из JSON вместо БД не подставляется.

Переход выполняется в окно остановки записей: остановите приложение/доступ администраторов, сделайте свежую зашифрованную копию, запишите контрольные количества. На машине с исходным `data/` задайте секреты подключения и выполните:

```text
npm ci
npm run db:migrate
node tools/database.cjs import
npm run db:verify
```

Для импорта `BELES_VERIFIED_BACKUP` должен указывать на JSON-манифест успешно проверенной копии. `BELES_STORAGE_DIR` указывает на корень с `data/` и `uploads/`. CLI импортирует каталог, аккаунты, обращения, интеграции, медиаметаданные, дизайн/историю и аудит одной транзакцией. Старые сеансы намеренно не импортируются: после переключения нужно войти заново. Пароли не пересчитываются. Файлы изображений/PDF и неизменяемый `site-original.html` остаются отдельно от БД.

Схема повторяемая; импорт с тем же хешем снимка не повторяет запись. Другой снимок или уже занятая БД отклоняются. В исходном каталоге есть две строки с ключом `product:mondo-motors-63446` и одна запись с маркером бренда `—`: они сохраняются. Технический `record_id` различает повторения, внешний бизнес-ключ и порядок не меняются. У новых записей проверяется уникальность бизнес-ключа. Маркер `—` остаётся в исходном payload, FK бренда для него равен NULL.

Для внешнего VPS используйте отдельного пользователя/БД, PostgreSQL с TLS, сертификатом на имя хоста и ограничением firewall до приложения/backup-хоста. Настройте `pg_hba.conf` с `hostssl` и SCRAM. Проверка сертификата включена по умолчанию; для своей CA задайте `DATABASE_CA_PEM`. Параметры `sslmode` в URL не могут отключить проверку. `PGSSL_DISABLE=true` допустим только в изолированном локальном тесте. Пул ограничен пятью соединениями, максимум десять, есть тайм-аут подключения и SQL.

Откат до открытия записей: остановить приложение, убрать `DATABASE_URL`, вернуть неизменённый исходный JSON и прежнюю версию кода, проверить вход/счётчики, запустить. После новых записей в PostgreSQL такой откат потеряет изменения: сначала необходим согласованный экспорт/восстановление снимка. Нельзя просто переключить источник во время работы. Реальное сетевое подключение и полный откат на вашей БД ещё требуют её настройки.

## Файлы и место

`MEDIA_DRIVER=volume` сохраняет существующий Railway Volume. `MEDIA_BUDGET_BYTES=1000000000` — бюджет приложения, не увеличение фактического диска. Раздел «Сховище та журнал» показывает изображения, PDF, шрифты, прочее, кеш, общий размер и фактически свободные байты. На исходном рабочем Volume около 38 МБ свободно при размере файловой системы около 433 МБ. БД, файловое хранилище и оперативная память — разные ресурсы; PostgreSQL не увеличит место для PDF.

Загрузки идут потоком во временный файл. Изображение — до 20 МиБ, PDF — до 60 МиБ, одна обработка одновременно. Подпись растра проверяется до декодирования, SVG не принимается; предел — 40 миллионов пикселей. Новые изображения поворачиваются по EXIF, уменьшаются до 2400×2400 без увеличения маленьких, сохраняются WebP quality 88 с альфой без EXIF. Имя — SHA-256 содержимого, одинаковые результаты не размножаются. Остаётся резерв места; при нехватке загрузка отклоняется, каталог не меняется. Каталог содержит только ссылки/тексты, бинарные медиа в RAM целиком не читаются. Списки админки показываются по 40 записей.

При `PDF_OPTIMIZE=true` Linux-образ использует qpdf + Ghostscript `/printer`, проверяет PDF и количество страниц, оставляет меньший результат. Ограничения дочернего процесса: 512 МиБ адресного пространства, 30 секунд CPU, 40 секунд общего времени, 60 МиБ результата. Превышение/ошибка отклоняет загрузку; прежний файл не меняется. Это не антивирус и не доказательство читаемости любого PDF: для существующих презентаций нужна визуальная сверка. При отсутствии инструментов/выключенной настройке PDF сохраняется без заявления об экономии.

`node tools/media-plan.cjs` после настройки `BELES_VERIFIED_BACKUP` формирует `dist/media-proposal/report.json`, ничего не переключая. `--keep-proposals` оставляет только предлагаемые новые копии в dist. Перед заменой существующих ссылок проверьте качество, прозрачность, крупный просмотр и экономию; оригиналы не удаляйте. Первичный отчёт сверяется с хешами резервной копии. Массовое перекодирование эффективных AVIF/WebP может увеличить расход диска, пока сохранены оригиналы.

Очистка кеша удаляет только собственные временные файлы старше суток и показывает реально освобождённые байты. Проверка сирот учитывает каталог, аккаунты/аватары, текущий/исходный/исторические шаблоны, предыдущий каталог и статические скрипты/стили. Дополнительно исключаются файлы моложе семи дней. Удаление требует свежего отчёта, подтверждения, повторной проверки ссылок и недавней аутентификации. Автоматически оно не выполняется. Для PostgreSQL/нескольких процессов онлайн-удаление намеренно закрыто: нужен режим остановки записей и отдельное подтверждение, чтобы исключить гонку с другими экземплярами.

## S3 или файлы на своём VPS

Поддерживается S3-совместимый API. На VPS можно использовать отдельный S3-совместимый сервер за HTTPS, например MinIO: закрытая административная консоль, отдельный bucket `beles-media`, отдельный ключ приложения с доступом только к объектам этого bucket. Публично разрешаются только GET/HEAD через отдельный media-домен; PUT/DELETE/List требуют подписи SigV4. Не открывайте запись посетителям. Ограничьте firewall, включите TLS с проверяемым сертификатом, резервирование и квоту. Приложение не создаёт VPS, bucket или платный тариф.

Задайте `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_FORCE_PATH_STYLE`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `MEDIA_PUBLIC_URL`. URL публичного media-домена не должен содержать секретов. Для PDF/font задайте CORS GET/HEAD для домена сайта и необходимые Range-заголовки; запретите исполнение HTML/SVG-скриптов, используйте отдельный домен без административных cookies.

Порядок переноса:

1. Остановить записи и проверить свежую внешнюю копию.
2. `node tools/media-copy.cjs` — показать объём без записи.
3. `node tools/media-copy.cjs --copy` — скопировать, перечитать каждый объект и сравнить SHA-256. Чужое отличающееся содержимое не перезаписывается. В БД/JSON записывается манифест, переключение ещё не выполняется.
4. Проверить публичные GET/HEAD, Content-Type, Range, CORS, превью/PDF на вашем endpoint.
5. Только затем задать `MEDIA_DRIVER=s3` и `MEDIA_READ_REMOTE=true`, перезапустить. Существующие `/uploads/...` перенаправляются на media-домен, новые загрузки получают его адрес. Без проверенного манифеста переключение отклоняется.
6. Сверить все ссылки и контрольные суммы. Оригиналы Volume сохраняются. Возврат `MEDIA_READ_REMOTE=false` возвращает чтение старых локальных файлов; новые S3-файлы перед полным откатом нужно отдельно скопировать обратно и проверить.

Заполнение диска не вызывает автоматический переход на другой драйвер. Диск VPS/S3, трафик, запросы, PostgreSQL и резервные копии могут оплачиваться отдельно. Квоту и срок бесплатного тарифа подтверждает владелец у своего провайдера.

Для PostgreSQL на отдельном backup-хосте установите подходящий `pg_dump`, задайте секрет `DATABASE_URL`, проверяемую CA и разные `BACKUP_OUTPUT_DIR`/`BACKUP_KEY_DIR`, затем `node tools/backup-database.cjs`. Дамп шифруется потоком, пароль передаётся дочернему процессу через окружение, не печатается. Медиа копируются отдельно, а `APP_ENCRYPTION_KEY` хранится в менеджере секретов: без него после восстановления недоступен TOTP-секрет. Проверка GCM не заменяет пробное восстановление `pg_restore` в изолированную пустую БД и сверку медиа.

Нельзя удалять единственную проверенную копию из-за возраста; ротация требует подтверждённой новой копии. Для S3 включите отдельный защищённый backup-bucket/версионирование и ограничьте право удаления.

## Railway и VPS

Развёртывание включает корневые runtime-модули `.cjs`, `package.json`/lock, `db/`, `tools/`, `public/`, `data/base.html`, стартовый `data/catalog.json`, Dockerfile и entrypoint. Никакие `dist/`, ключи, admin/sessions/audit/feedback, рабочие настройки и 400 МБ медиа в образ не отправляются. Docker устанавливает runtime-зависимости, qpdf/Ghostscript/prlimit, затем запускает Node от непривилегированного пользователя. Volume монтируется в `/beles-storage`, `BELES_STORAGE_DIR` должен совпадать. Новый деплой не заменяет существующий каталог начальным файлом.

На VPS используйте постоянные каталоги с владельцем пользователя приложения, доступом 0700 для приватных данных и 0600 для секретов, systemd с `Restart=on-failure`, Node 22+, `npm ci --omit=dev`, обратный прокси с HTTPS и ограничением размера тела 60 МиБ. Не публикуйте `/data`, `/tools`, исходники и конфигурацию как статическую папку. После миграции проверяйте `/health`; не принимайте трафик при 503.

`TRUSTED_PROXY_CIDRS` заполняется только документированными адресами непосредственного proxy. По умолчанию X-Forwarded-For не принимается; это защищает от подделки IP, но несколько посетителей за одним proxy могут разделять лимит. Не ставьте `0.0.0.0/0`. Нужна проверка реальной цепочки Railway/VPS перед тонкой настройкой лимитов. Для объёмных атак используйте ограничения соединений/частоты на edge/proxy и WAF/CDN, с учётом стоимости и политики провайдера; приложение не гарантирует защиту от DDoS.
