# Размещение Beles

Статус на 17 октября 2026: приложение размещено в Railway; опубликованы
лимит двух администраторов и собственная аналитика. См. ANALYTICS_RU.md.

Сайт: https://brilliant-fulfillment-production-38a1.up.railway.app
Админка: https://brilliant-fulfillment-production-38a1.up.railway.app/admin
Проект: ee1e2642-d110-4109-86c4-7a2890a14bac
Сервис: 6c99fbf2-ab4d-46dc-af4d-037d703e2efe

Railway использует диск `/beles-storage`: каталог и учётная запись в `data/`,
медиа в `uploads/`. Переменная BELES_STORAGE_DIR задаёт этот корень.
Проверено: HTTPS-страница и админка, все 492 медиафайла (статус и размер),
частичная загрузка PDF, сохранение хеша каталога и всех файлов после restart.
При первом запуске каталог копируется из образа, при следующих существующий
каталог сохраняется. Шаблон страницы берётся из кода приложения.
Все 492 исходных медиафайла перенесены на диск отдельно из-за лимита загрузки
архива. Они занимают около 400 МБ; после загрузки на диске доступно около
40 МБ по df. Не загружать большие файлы без переноса медиа или расширения
диска. Расширение может потребовать платного тарифа и здесь не выполнялось.

Для обновления кода используется компактная папка `dist/railway-deploy`:
server.cjs, render.cjs, storage.cjs, accounts.cjs, analytics.cjs, package.json, Dockerfile,
docker-entrypoint.sh, public/, data/base.html и data/catalog.json.
Перед повторной публикацией её нужно обновить из исходников.
Не загружать весь dist: там архивы и кеш CLI. Не заменять рабочий каталог
на диске стартовым каталогом из исходников.

Ниже — первоначальные сведения для переноса на отдельную виртуальную машину.

Подходящий бесплатный вариант: Oracle Cloud Always Free, виртуальная машина
с Ubuntu и постоянным диском. Создавайте только ресурсы в пределах Always Free
в домашнем регионе. Доступность свободных машин не гарантирована; неактивные
машины могут быть отозваны. Для регистрации Oracle требует проверку карты.

Источники, проверенные 16 октября 2026:
- https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm
- https://www.oracle.com/cloud/free/faq/

Бесплатный Render не подходит для текущего хранилища: изменения локальных
файлов теряются при остановке или перезапуске. Каталог, обращения, учётная
запись администратора и новые загрузки должны храниться постоянно.
Источник: https://render.com/docs/free

## Что подготовлено

`dist/beles-deploy.tar.gz` содержит сервер, шаблон, каталог, локальные медиа,
админку, Dockerfile, Compose и инструкции. Это пакет для новой установки,
а не резервная копия существующего сервера. Пароли, обращения, .env и настройки
IDE в пакет не включены. Рабочие файлы data и uploads сохраняются отдельно
на сервере через bind mounts, уже описанные в compose.yaml.

## Что нужно для загрузки

- Созданная виртуальная машина или доступный аккаунт хостинга.
- IP/имя сервера, SSH-пользователь и порт.
- Путь к локальному SSH-ключу; содержимое закрытого ключа в чат не требуется.
- Домен можно сообщить позже.

Перед распаковкой проверяется, что целевая папка новая или пустая: содержимое
существующей установки нельзя заменять этим стартовым каталогом.
После передачи архива нужно проверить ОС, установить среду запуска, дать
процессу права записи в data/ и uploads/ и запустить один экземпляр приложения.
Для Docker пользователь node имеет UID 1000; права bind mounts на хосте
должны позволять этому пользователю запись.

В compose.yaml пока сохранён пример домена belesbrands.com.ua. Перед публичным
запуском его необходимо заменить подтверждённым доменом и настроить HTTPS.
Для предварительной проверки без домена можно запустить Node.js на loopback
и открыть его через SSH-туннель; PUBLIC_URL при этом не задавать,
COOKIE_SECURE=false. Не использовать пример HTTPS-домена для такого просмотра.

После подключения домена: настроить DNS, HTTPS-прокси, PUBLIC_URL и
COOKIE_SECURE=true. Создать администратора по одноразовому setup-коду из логов,
проверить сайт, загрузки, вход и сохранение данных после перезапуска.
